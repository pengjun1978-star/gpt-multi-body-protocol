# v1.1.1 Hotfix

用户已显式将 v1.1.1 从 FROZEN 状态 REOPENED FOR HOTFIX。GA commit、tag 和 release 仍是历史发布证据，本分支不移动或覆盖它们。

## 强制决策链

`Business Intent → Business Task Identity → Execution Ownership → Stage/Step → Runtime → Body → Compute`

一个 `business_task_id` 贯穿全部 stage、纠错、收件人修订、附件替换和重试；默认只有一个 canonical execution thread/lineage。Stage ≠ Task，Correction ≠ New Task，Action ≠ New Execution。

## 运行时与邮件 Gate

`resolve()` 先识别 continuation/correction，并 exact-resume 原 owner；无法恢复返回 `CONTINUATION_DISPATCH_BLOCKED`，禁止创建替代线程。重复 handoff 返回 `DUPLICATE_EXECUTION_BLOCKED`。

邮件 stage 为 `PREPARE → MATERIALIZE_MD → USER_REVIEW → VERIFY_RECIPIENTS → VERIFY_ARTIFACT → SEND → DELIVERY_CONFIRMATION`。发送前必须验证 task 绑定、current artifact、路径、字节数、SHA-256、版本/批准状态和 To/CC 当前性。用户否决附件后进入 `ARTIFACT_INVALIDATED` / `BLOCKED_BY_ARTIFACT`，新文件完成 materialize + verify + current/approved 后才可继续。

## Live regression checklist

1. 创建研发会议业务目标并记录唯一 `business_task_id`、canonical thread/session。
2. 生成并物化目标 MD，登记 bytes/SHA-256/version/current/approved。
3. 核验研发 To/CC，进入发送前 Gate。
4. 输入“地址没问题，但是 md 文件不是这个”，确认旧 artifact invalidated、SEND blocked、task/thread 数量仍为 1。
5. 物化正确 MD并完成 hash/bytes/approval 验证，确认仍使用原 task/lineage。
6. 继续发送并核对 current artifact 与 current recipients；保存最终 receipt。

平台层仍可能限制 ChatGPT UI 对原始 Local Codex thread 的直接 exact-resume；协议代码对此返回阻断证据，不能用新 thread 冒充继续。
