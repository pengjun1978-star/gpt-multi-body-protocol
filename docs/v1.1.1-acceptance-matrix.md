## Gate C — Return-to-Origin and ACK Return

Every dispatch persists the parent route, task, generation, Codex thread/session,
branch and timestamps. C1 is PASS. The parent GPT probe was visible in and
consumed by the original parent conversation; `PARENT_GPT_UI_VISIBLE_ACK`
establishes C2 PASS.

C3 uses `ACK_CREATED → ACK_DELIVERED_TO_CODEX → GPT_ACKED`. Each ACK is bound to
`callback_event_id`, `task_id`, `execution_generation`, and parent route. The
canonical Registry stores the ACK identity and applies it idempotently. An
unavailable return path persists the ACK as `OUTBOX` for retry. Successor and
exact-resume generations use the inherited parent route.

The implementation and tests are in `ack_return_channel.py`,
`task_registry_sqlite.py`, and `test_ack_return_channel.py`. A supported
parent-to-Codex machine transport with a readable ACK remains unavailable, so
C3 and overall Gate C remain `PLATFORM_BOUNDARY`. C1 and C2 remain PASS.

## Mandatory Return-to-Origin Rule

For every Parent GPT delegation, `COMPLETED`, `PARTIAL`, `BLOCKED`, `FAILED`,
and `CANCELLED` require an active canonical callback to the original Parent GPT.
Office inbox/outbox is fallback only and cannot substitute for that return.

## Continuation Dispatch Guard

Same-task continuation resolves the existing parent/task mapping and exact
canonical Codex session. An unavailable or mismatched session produces
`RESUME_FAILED/BLOCKED`; create-new is prohibited. No new task, thread, or
session may be created by continuation.
