# Gate C — Return-to-Origin reliability

Every dispatch persists `parent_gpt_conversation_id`, origin route, `task_id`,
generation, Codex thread/session, branch and timestamps. Successor bindings use
`inherit_task_id`; missing parents fail closed. Canonical envelopes carry
status, generation, body, thread, evidence, receipts, limitations, next action
and `callback_event_id`. Delivery is `PENDING → ACCEPTED → ACKED`; `OUTBOX`
holds unavailable routes. `ACCEPTED` records adapter acceptance only. The
current platform has `PLATFORM_BOUNDARY`: no supported adapter proves parent
GPT UI visibility, so Gate C cannot claim full end-to-end parent UI delivery.

Regression coverage: new thread and successor inheritance, route-unavailable
outbox recovery, callback idempotency and single ACK are in
`test_return_to_origin.py`.
